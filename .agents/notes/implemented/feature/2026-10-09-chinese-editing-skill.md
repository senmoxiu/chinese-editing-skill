# Agent Note: 中文编辑 skill 的范围与来源

Status: implemented

## Problem

中文排版、知识库审校和技术界面文案需要不同的编辑强度。现有来源分别偏重 Markdown 自动修复、正式文体和产品技术表达；直接叠加会在引号、单位间距和语气上发生冲突。

## Decision

本仓库提供可独立安装的 chinese-editing skill，以任务意图区分排版校对、文档审校、技术及界面文案。规则按需读取，源文件语法、事实和作者语气有明确保护边界。默认简体中文横排弯引号，项目约定可覆盖。发布目标是公开 GitHub 仓库，安装默认采用项目范围。

入口、参考和来源记录位于 skills/chinese-editing；安装说明、检查工具与评估样例留在仓库级。首版不携带自动修改正文的脚本。

## History audit

新仓库没有既有笔记。父知识库中的资料重组与简历证据笔记与本决策无关；本仓库不复制它们，也不改动父项目规则。

## Alternatives considered

- 直接采用 chinese-copywriting-linter：优点是已有可执行的 Markdown 检查及修复。其引用风格和部分替换行为不符合本项目边界，且无法承担跨载体文案审校。
- 直接采用 chinese-document-style：优点是文档结构和事实保真要求完整。其默认正式文体不适合所有知识笔记、博客和品牌文本。
- 直接采用 tech-doc-style-chinese：优点是技术及界面语义覆盖充分。单独采用不能体现用户希望保留的窄范围排版入口和统一默认排版选择。
- 把三套正文合并：优点是材料齐全、遗漏少。冲突与常驻上下文都会增加，因此只归纳可迁移原则，并分开语境。

## Verification

- skill-creator 的 quick_validate.py 已通过；本仓库 scripts/validate.py 检查 YAML、相对文件链接、四个固定版本来源、笔记和 14 个行为案例的数据结构。
- tests/test_validate.py 检查正常包，以及引用缺失、引用越界、重复案例和入口名称错误的拒绝行为。
- 作者按案例走查了只排版、检查不写文件、技术字面量保护和未知状态处理；尚未在独立模型中执行 14 个案例，不报告模型通过率。
- 本仓库没有 Node.js 工具链，不添加仅为包装校验存在的 package.json；笔记格式校验由上述 Python 入口承担，不能运行 npm run verify-notes。

## Consequences

单个安装目录可按需覆盖不同中文编辑任务，省去安装多份重叠规则。维护者需要持续处理来源间的规则差异，且模型仍可能误判文本角色；无自动格式化脚本意味着不能提供确定性批处理保证。上游内容与授权分别记录，未明确授权的内容仅作概念参考，不复制实现或原文。出现大批量格式化需求时再评估具有语法保护和失败退出测试的检查器。
