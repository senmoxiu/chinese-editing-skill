# 行为验收

`cases.json` 是人工评估任务集，不是已经通过的模型测评。用同一份 skill 在目标 Agent、模型和推理设置下逐项运行，保存原始输出，再按 rubric 判断。

## 执行方式

1. 创建临时项目并安装完整 skill；对普通任务使用正常发现机制，对显式调用另开一轮测试。
2. 每个案例使用新会话，输入 `request`。不要把 `rubric` 提供给被测模型。
3. 需要文件的案例先在临时目录创建该文件；记录操作前后的哈希或差异。仅审阅案例必须确认文件没有改变。
4. 保存原始回复、相关工具记录、模型标识、客户端版本和日期。对评分点逐项给出通过／未通过／无法验证及依据。
5. `none` 模式应直接处理原任务；通过工具轨迹检查是否误加载 skill，不能仅凭最终回复猜测。

`evals/runs/` 默认忽略，避免把真实项目内容和会话记录意外发布。分享结果前需检查其中是否包含私人信息。仓库中的案例均为合成输入。

## 验收重点

- 代码、URL、占位符及引用是否保持准确。
- “只检查”和“只排版”是否限制了文件操作与改写范围。
- 条件、否定、数值和不确定性有没有改变。
- 作者语气和项目风格是否得到保留。
- 技术提示是否忠于实际业务状态。

初版完成的是作者规则走查与静态包校验，尚无独立模型运行结果。不得把样例数量或校验通过当作跨模型通过率。
