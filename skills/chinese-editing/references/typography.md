# 排版校对

仅在处理排版、标点或术语拼写时读取。适用于可编辑正文；源代码和排版载体本身遵循各自语法。

## 先识别文本角色

把读者看到的自然语言与技术字面量区分开。例如 `下载API文档` 可改为 `下载 API 文档`，而字段 `api文档`、URL、文件名和产品注册名称不能据此改名。终端输出和教程反例也不能当作正文修正。

## 空格、字符与标点

- 默认在中文与相邻的拉丁文字、阿拉伯数字之间留一个普通空格，例如 `共 6 个 API`。不要插入全角空格或连续空格模拟布局。
- 中文全角标点紧邻正文，不额外留空格。完整英文句子的内部按英文标点处理。
- 普通数字用半角；序号、型号、时间、小数、负号和版本作为整体处理，不拆开 `v2.3.1`、`09:45`、`-0.25`。保留精度和有效位数。
- 引号默认外层“”、内层‘’。已有明确地区或品牌约定时沿用；原文引用不因项目换风格而改写。
- 中文省略与插入说明可用 `……`、`——`；不要改 Markdown 分隔线、命令参数、英文标识符中的符号。
- 重复感叹号在说明文中通常可收敛；聊天记录、人物对白、广告语的强调效果先判断用途，不设无条件禁词。
- 技术名称按可靠的官方形式或项目词表处理。`github` 可能是命令、账号或路径，不能见到就换成 `GitHub`；`H5` 也不自动等同于 HTML5。

## 数值与单位

正文默认把数字与字母单位分开，如 `64 MB`、`250 ms`。角度 `30°` 与温度 `30 °C` 区分处理。普通产品文案默认使用 `25%`；科研、出版或行业的明确规范可覆盖这些排版选择，不宣称本文件代表全部计量标准。

不改变上下界、单位或数值精度；不把“约 8 万”改成精确的 `80000`。不将百分比变化与百分点混写。缺失单位先提示，不能自行猜补。

日期只调整已知信息的表现形式；不把 `03/04` 自行解释为某一天，也不凭执行环境补时区。数值区间可使用“至”提高可读性，但不得改变开闭区间或版本约束表达式。

## Markdown 与其他载体

- 保留围栏代码（反引号及波浪线）、缩进代码、行内代码、数学块、HTML、YAML frontmatter、脚注和引用定义的结构。
- 链接按显示文字判断边界。例如 `查看[帮助](https://example.org/help)。` 无须为中文链接增加额外空格；`阅读[API](https://example.org/api)指南。` 可改为 `阅读 [API](https://example.org/api) 指南。` 目标地址不变。
- 行内代码只处理标记外侧的间距。不要改代码内部的中文字符串、全角数字或引号；需要修改字符串时必须来自另一个明确的文案任务。
- 保留显式换行、列表缩进、表格转义和引用块。仅排版不默认合并所有硬换行，是否重排段落服从项目约定。
- Obsidian 的 `[[双链]]`、嵌入、别名与块 ID 是结构；不得把它们拆成普通标点。中文标点两侧留白规则也不能吞掉用于布局的结构空白。
- JSON、YAML、HTML 和本地化资源需先识别可编辑值。保护 `{name}`、`%s`、`{{count}}`、ICU 消息分支与转义序列；不能只靠全局正则替换。
- Word、PDF、网页的换行和禁则由排版工具或浏览器共同决定。未检查渲染时，只报告文本层面的修改。

## 校对样例

输入：`下载JSON报告,文件大小为32MB。`

校对：`下载 JSON 报告，文件大小为 32 MB。`

输入：``配置项为 `{"标题":"版本３"}`，路径为 `docs/版本３.md`。``

校对：原样保留。即使字面量看起来不符合正文习惯，也不能改变其值。

多个规则可成立时，沿用已声明规范；没有声明且影响较大时提出可选建议，不把风格差异写成错误。
